Supporting code and data for the note
"Least lengths of Aoki's exceptional Hodge classes on Fermat varieties, and degrees with four prime factors"
================================================================================================================

Status: accompanies the note (K. Saller, 2026), DOI: 10.5281/zenodo.23571028; not peer reviewed.

Setting. X^n_m is the Fermat variety of degree m and dimension n. Its Hodge classes are described by Shioda's
Hodge elements, integer combinations of the classes (a) of the residues a mod q, q | m. B_q is the group of Hodge
elements of degree q, D_q the group generated by the linear elements (a) + (-a), and S_q the group generated by
the standard elements of Aoki (lifted from all degrees dividing q). Aoki's exceptional element xi_q is defined for
the q in Q, the products of a positive even number of distinct elements of {4, 3, 5, 7, 11, ...}. The length l_{2,d} of a
class is the least number of entries of an element of the class modulo D_d + S_d at the level d (q | d). The note
studies these lengths for q = l p and q = 4p, and the degrees q with four prime factors, such as 420 = 4.3.5.7.

Role of the computations. The note's section "Computations" lists eight items; Section 3 below says which script
makes each check. Most of them check statements that the note proves by hand. The following rest on
computations, as the note says where they are stated:
  - the values of l_{2,d}(xi_q) in the table after Theorem 6.3 (d = 2q) and in Remark 6.6 (further levels):
    integer programs give upper bounds, attained by explicit tuples checked in exact arithmetic, and an
    exhaustive search gives lower bounds; a value is called exact only where the two agree or a theorem gives
    it. Theorem C(b) and Corollary 6.5 use the search for q = 51, 65, 69 at d = 2q, and l_{2,102}(xi_51) = 7 is
    such a value;
  - the last statement of Theorem 8.1(c) (the single class), Theorem 8.4 for r >= 11, Remark 9.4, and the
    statement after Proposition 9.1 about the 579 degrees q < 20000 with four prime factors.
The other numbers quoted in the note are checked by the scripts below. Corollary 7.4 (the second sentence of
Theorem D(a)) is proved in the note from results of Kubert; the Smith normal forms at 420, 660, 780 (item 8(b))
confirm it there.

Not checked by any script: the proofs for all q (the scripts treat finitely many degrees), the cited theorems (of
Aoki, Shioda, Kubert, Yamamoto, Peterson, and of Miranda, Movasati, Rufino and Villaflor), and the algebraicity of
any class. Nothing here bears on the Hodge conjecture itself.

Labels. The headers and output lines of the scripts in fermat-parity/code use the numbering of the working
document from which the note was written (NOTE.txt, not part of this repository), for example "Theorem 12" or
"(B)". Section 4 below translates these labels into the numbering of the note. The scripts in fermat-parity/checks
use the numbering of the note; those in fermat-parity/certify use the working document's numbering ("Section 7",
"Theorem 18").

1. Requirements
---------------
Python 3 with python-flint and numpy; scipy (its HiGHS solver) for lifts.py and the scripts that import it; z3
(the package z3-solver) for z3check.py only. compare_outputs.py and the scripts in fermat-parity/checks use the
standard library only. Tested versions: Python 3.12.9, python-flint 0.9.0, numpy 2.1.3, scipy 1.15.2 (HiGHS 1.8.0),
z3-solver 5.1.0, on Windows 10. The reference outputs in fermat-parity/outputs were made in the working tree; the
platform and the versions of that run are not recorded in them. parity.py and lifts.py start 3 worker processes,
certify.py as many as its option --procs says.


2. Layout and how to run
------------------------
fermat-parity/code/      parity.py, structure_lp.py, lifts.py, fourprimes.py, xi420.py
fermat-parity/outputs/   their reference outputs: NAME.json (the results) and NAME.out (the screen output)
fermat-parity/checks/    aoki_xi.py, check_lifts420.py, part2_checks.py; their screen outputs in checks/outputs/
fermat-parity/certify/   certify.py and cert_core.py (exhaustive search), summarize.py, z3check.py, and their
                         result files NAME.json and NAME.out, with the summary table summary.out
cyclic-covers/code/      composite.py, obstruction.py, cyclic.py   (libraries, see below)
fermat-frontier/code/    fermat_tools.py                            (library)
ts-powers/code/          v2_exotic.py                               (library)
run_all.sh, run_certify.sh, compare_outputs.py

The scripts find the libraries by relative paths, so the folder layout must be kept. The libraries come from other
folders of the working tree. They are included because the scripts import functions from them; the checks that
their own headers describe belong to other working documents and are not run here. (ts-powers/code/v2_exotic.py
is not part of the repository HC-ts-powers.)

From the top folder of this repository:
    sh run_all.sh rerun
    python3 -I compare_outputs.py fermat-parity/outputs rerun/outputs
    python3 -I compare_outputs.py fermat-parity/checks/outputs rerun/checks
run_all.sh runs the five scripts of fermat-parity/code, each with its output file as argument (for example
python3 -I fermat-parity/code/parity.py OUT.json), and the three scripts of fermat-parity/checks, and writes the
results into rerun/. Each script of fermat-parity/code prints "ALL CHECKS PASS: True" as its last line when all
its checks pass. compare_outputs.py compares each .json and .out file with the reference after removing what
depends on the run rather than on the mathematics: run times, the order in which parallel workers finish, the
particular optimal tuple returned by the integer-programming solver (its length is compared), option keys that
older result files lack, and z3 queries that reached their time limit in one of the two runs (its docstring gives
the details). Its expected last line is "ALL EQUAL". The shell scripts call python3; set the environment variable
PYTHON to use another interpreter name (for example PYTHON=python).

certify.py, summarize.py and z3check.py write their results next to themselves. run_certify.sh reruns all of them
with the options recorded in the shipped result files, and so overwrites those files; run it in a copy of the
repository, for example
    cp -r . ../copy && sh ../copy/run_certify.sh
    python3 -I compare_outputs.py fermat-parity/certify ../copy/fermat-parity/certify
certify.py reads the integer-program optima and representatives from fermat-parity/outputs/lifts.json (the
reference output) and re-implements the lattices independently of lifts.py (see Section 3, item 5).

Changes against the working tree: in parity.py, a docstring said "95 degrees" where the check covers 97 (as its
output says); in obstruction.py, one docstring line named a folder of the working tree, now replaced by a
description of the two test tuples it refers to; in cert_core.py, the path of the working tree is replaced by the
top folder of this repository. run_all.sh, run_certify.sh and compare_outputs.py are new. The other scripts of
the working folder (averaging.py, structure.py, twist.py, twist_lp.py, eightp.py: the averaging identity, the base
span, the twisting groups and the degrees 8p, which the note does not treat) are not included. All other files
are unchanged.


3. The scripts and the items of the note's section "Computations"
--------------------------------------------------------------------
Statement numbers are those of the note; labels in parentheses, such as (B), are those of the scripts.

Item 1 (lattices and classes) -- lifts.py: the lattice L_d, the span of the standard tuples of all degrees dividing
  d, the Smith normal form of the quotient and the class functionals F; cert_core.py recomputes all of them
  independently and compares them with lifts.py. The scripts take the standard tuples as in [MMRV, Def. 3.7]
  (p not dividing i; tuples with an entry 0 dropped) in every degree e | d and lift them to d; check_lifts420.py
  takes Aoki's standard elements of degree d ([Aok83, p. 36]: p i != 0, d/2). Together with D_d both span the
  same group D_d + S_d: sigma_{p,i} depends only on p i mod d, every admissible value of p i comes from a lifted
  tuple, and the lifted tuples with p i = d/2 lie in D_d.
Item 2 (Section 4) -- parity.py (A): xi_q from the recursion, Hodge, Lemma 4.1, the count rule of Theorem 4.3 and
  Remark 4.4, for all odd q = l p <= 400 (for 4p the order-4 part); (B): on a lattice basis of B_q, which counts are
  nonzero, for the 97 degrees l p, 4p <= 400 with l <= 19. aoki_xi.py: the second program, written from Aoki's
  article alone (pages 26, 28 and 37 of [Aok83]): all two-factor degrees q <= 600 and all choices of primitive
  roots, both signs; and the 39 four-factor degrees q <= 3099 (Theorem E).
Item 3 (Section 5) -- structure_lp.py (N): the tuples constructed in the proofs of Theorems 5.1 and 5.2, for all
  odd l p <= 1000 and all 4p, p < 1000; (O): the formula for L against the 105 entries of [MMRV] Table 1.
  structure_lp.py also checks Theorems 3.1 and 3.3 and Corollaries 3.2 and 3.4 on lattice bases and on all Hodge
  4-tuples ((M), (P)); the note proves these by hand.
Item 4 (integer programs, Section 6) -- lifts.py (Q): degree 2q, two independent integer programs for odd q <= 150;
  (S): l_{2,kq}(xi_q) for k <= 6 at the 16 two-factor degrees q <= 69 and for k <= 12 at 44, 51, 52, and the sums
  with known algebraic classes; (T): the levels of [MMRV] Table 3. The optima are upper bounds; each representative is
  checked in exact arithmetic.
Item 5 (exhaustive search) -- certify/certify.py with cert_core.py: for 147 pairs (level d, element xi) at 116
  levels, an exhaustive meet-in-the-middle search that no element of the class has length <= B, every key
  coincidence re-checked exactly. summary.out lists every job: the solver's value, the exact check of its
  representative, the certified lower bound and the status (113 CERTIFIED, 34 LOWER BOUND ONLY).
Item 6 (z3) -- certify/z3check.py: z3_P1 (d = 2q, q <= 69: unsat below the value, sat at it), z3_B6_q51, z3_B6_q65,
  z3_B6_q69 (no element of length <= 6). "unknown" means the time limit was reached; it proves nothing. Whether a
  query finishes within the limit depends on the run (Section 5).
Item 7 (Theorem 6.4) -- lifts.py (R): the witness families of the proof at 33 levels r q.
Item 8 (Sections 7-9) --
  (a) fourprimes.py (AM): the relations of Theorem 7.1 and their rank; (AN): the coset counts of Proposition 7.2;
      (AQ): the identities of Proposition 7.3, at 420, 660, 780, 924, 1155.
  (b) fourprimes.py (AN): Corollary 7.4, as a confirmation at 420, 660, 780: the Smith normal form of
      B_q / (D_q + S_q) and the rank of the six lifts.
  (c) fourprimes.py (AO), (AQ): Theorem 8.1(c), the element Xi, its per-level minima and the seven counts.
  (d) fourprimes.py (AO): the product elements of Remark 8.2 at 660, 780, 1155, and Pi + (693) at 924.
  (e) xi420.py (AT) and check_lifts420.py: the maps of the proof of Theorem 8.4 at 840, 1260, 2100, 2940 and 420 r,
      the 576 linear systems for Psi; fourprimes.py (AP): Theorem 8.3 at 1260.
  (f) xi420.py (AR) and aoki_xi.py: Proposition 9.1(a), (c), Proposition 9.2, the 579 degrees q < 20000.
  (g) xi420.py (AS): Remark 9.4 (the 128 products of half systems, the 64 classes, the completion of length 17);
      check_lifts420.py: Peterson's w_1, w_2.
  (h) part2_checks.py: the third program, written from the text of Sections 7-9 of the note.
Not used by the note: parity.py (C), (D), which concern the base span (the span of the linear, standard,
  Lefschetz and curve-pair classes; structure_lp.py and lifts.py call the same library with the span of the
  linear and standard classes only, D_q + S_q); fourprimes.py, in (AN) the sign-blind witnesses and in (AQ) the
  cyclic-cover families; xi420.py (AU) (counts at 1740, 2460, 2652 and at the levels with two factors). They are
  checks of statements of the working document that the note does not make.

5. Rerun
--------
When this repository was assembled, a copy of it was rerun on 22 October 2026 on the machine on which the
reference outputs were made, with the versions listed in Section 1: run_all.sh took 33 minutes and run_certify.sh
73 minutes. Every script of fermat-parity/code
printed "ALL CHECKS PASS: True", run_certify.sh reported "147 jobs, 116 levels: 113 CERTIFIED, 34 LOWER BOUND
ONLY", and the three comparisons of Section 2 ended with "ALL EQUAL". The rerun differed from the reference
outputs only in the respects that compare_outputs.py sets aside:
  - run times;
  - the order of the levels in the result files of certify.py;
  - some of the optimal tuples found by the integer-programming solver, of the same lengths, for example for
    q = 33 at d = 66 and q = 35 at d = 70 in lifts.json; the tuples printed in the note are those of the reference
    outputs;
  - the keys "extra" and "noextra" of "args", which the result files written by earlier versions of certify.py
    lack; the rerun, with the shipped version and these options at their default values, gave the same results;
  - z3_P1: with the time limit of 25 seconds, the query below the value finished for q = 57 in the reference run
    and for q = 35 in the rerun, and confirmed the value in both cases; for q = 51, 55, 65, 69 it reached the time
    limit in both runs. The runs with the bound 6 and a limit of 280 seconds gave the same results in both runs:
    no element of length <= 6 for q = 51 and q = 69, and the time limit for q = 65.


6. What the computations do not show
------------------------------------
- The scripts check finitely many degrees; the statements for all q are proved in the note.
- An integer-program optimum is a claim of the solver. The note uses it only as an upper bound, attained by a tuple
  checked exactly, unless the exhaustive search or a theorem of the note confirms it; the lower bounds printed by
  lifts.py are not used.
- The exhaustive search excludes all elements of length <= B in the class. Its reduction by the units that preserve
  the class rests on conditions checked exactly on generators of the unit group (see cert_core.py); a key
  coincidence of the hashed search is always re-checked exactly, so a wrong hash can only cost time.
- The cited theorems, in particular Aoki's Theorem D and the theorems that make the linear and standard classes
  algebraic, are not checked.
- Independence: aoki_xi.py was written from Aoki's article alone, without the other code; cert_core.py
  re-implements the lattices and the class functionals but takes the elements xi and the solver's representatives
  from lifts.py; part2_checks.py and check_lifts420.py were written from the text of the note. All scripts were
  written with the assistance of an AI system (Claude, by Anthropic), so they are independent only in that sense.
